# Keep paid processing separate from local availability

A new library must be useful before the user chooses a provider or spending limit. An available API key establishes credential readiness, not consent. Semantic search and the automatic-review default therefore have independent explicit opt-ins, with shared accepted budgets and a persisted accounting timezone. Enabling a capability does not start a full-library build or backfill.

Each intake records its processing choices at creation. Future-default changes cannot silently enlarge an existing job's authorization; later review is a deliberate transition on the same identity. The automatic-review switch describes future imports, while pause/resume governs already-authorized work. Local-only intake limits that operation, not every later explicit semantic sync involving the book.

Existing authorizations, completed stages, cached embeddings, cost reservations, and initial-build accounting survive migration. Older libraries keep their historical limits and period interpretation. Fresh users explicitly accept or edit the $10 initial/$10 monthly suggestions. These are per-library accounting limits, not provider-enforced billing caps. Conservative reservations and retained uncertain costs trade temporary availability for avoiding hidden paid replay.
